## 2026-11-17 SQL Server driver
- Task 1: `mssql` Cargo feature with `tiberius` 0.13 (rustls only, one rustls in the tree, no OpenSSL), TLS spike against a Docker SQL Server (`DBZILLA_TEST_MSSQL=1`).
- Task 2: `DriverId::SqlServer` with `MsSqlDialect` (`[ident]`, `N'..'` strings, `0x..` bytes, `GETDATE()`), capabilities, `sqlserver://` and `microsoftsqlserver://` URLs (port 1433), safe mode with the T-SQL parser, connection list and form entries. DDL: T-SQL `ADD`, `DROP INDEX .. ON`, `DROP CONSTRAINT`, `SELECT INTO` clone; altering columns, primary keys and triggers return a clear Unsupported error. MCP read-only queries are refused on SQL Server (no read-only transaction). `driver_for` installs `ring` as the rustls provider once, because `tiberius` also enables `aws-lc-rs` and the MySQL TLS client would otherwise panic.
- Task 3: `Dialect` gained `page_clause`, `row_limit_clause`, `extra_limit_blockers` and `select_top`. The data tab, export, editor row limit (`apply_row_limit_for`) and Copy Script As use them, so SQL Server gets `ORDER BY (SELECT NULL) OFFSET n ROWS FETCH NEXT m ROWS ONLY` and `SELECT TOP n`, with a single `ORDER BY` when the statement already sorts. Other dialects are unchanged.
- Task 4: SQL Server driver (`mssql.rs`): connect over TLS (PREFERRED and REQUIRED encrypt without verifying the self-signed certificate, VERIFY modes verify it, DISABLED encrypts only the login), timeout and readable login errors, version, databases, schemas and objects through `[db].sys.*` (no `USE`), ping, `set_database`. The session reconnects by itself when the socket dies and returns to the selected database. Table structure, queries, batches, cancel and database management follow in the next tasks. Integration tests run with `DBZILLA_TEST_MSSQL=1`.
- Task 5: SQL Server table structure (columns with type, length, precision, scale, identity, collation and default without the parentheses SQL Server adds; primary key, indexes with filters, foreign keys with actions and names, triggers read only, DDL of tables built from the structure and of views from `sys.sql_modules`) and the row estimate from `sys.partitions`. "Open definition" of a function or procedure reads `sys.sql_modules` of the right database.
- Task 6: SQL Server `query_stream`: first result set streamed in batches with back-pressure and a row limit, other result sets dropped, a timeout that drops the socket (the next call reconnects), and error messages from the server. `INSERT`/`UPDATE`/`DELETE`/`MERGE` without `OUTPUT` go through `execute` to report the affected rows; everything else (DDL, `USE`, `EXEC`) streams and reports none. Values: integers, floats, bit, text, guid, binary, decimal and money (as decimal text, four decimals), xml (text), dates and times (chrono), datetimeoffset.
- Task 7: SQL Server `execute_batch` (affected rows per statement, atomic batches in one transaction with rollback, the same `statement N failed` message as the other drivers), `create_database` (optional collation, only plain names accepted), `rename_database` and `drop_database` (the session leaves the database first and other sessions are rolled back, the database goes back to multi-user when the step fails).
- Task 8: SQL Server cancel: the token runs `KILL <spid>` on a second connection and the running query reports `Cancelled`; the connection reconnects by itself on the next call and returns to the selected database. `cancel_handle` reconnects first, so a token never holds the id of a dead session. The commit of pending changes opens its transaction with `BEGIN TRANSACTION` on SQL Server (a bare `BEGIN` starts a block in T-SQL). A timed out query needs no `KILL`: the server stops it as soon as the socket is dropped (tested).
- Task 9: process list for SQL Server (SPEC 11.4): running requests from `sys.dm_exec_requests` with session id, database, login, host, status, CPU time, elapsed time and statement text (own session left out) and Kill with `KILL <spid>;`, which ends the session and rolls back its transaction. The sheet and the safe-mode gate are the existing ones. Tested end to end against a real server.
- Task 10: SQL Server checked in the real app against a Docker server (connect from a `sqlserver://` URL, sidebar, Data tab with types, key and accents, Structure tab; screenshots `docs/screens/mssql-data.png` and `mssql-structure.png`). Found and fixed: the schema picker started in `public`, which does not exist on SQL Server, so the sidebar was empty; `Capabilities` now has `default_schema` (`public` on PostgreSQL, `dbo` on SQL Server) and `schema_or_default`. Data tab paging, the editor row limit and the `SELECT TOP` script are tested against a real server. README and FEATURES updated.
