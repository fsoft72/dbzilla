- Release 0.1.3.
- SPEC: removed plugins/custom scripts (§17), light and Auto themes, multi-window, connection sources and other team features (§6.8, shared query folder), multi-caret (§10.4) and split panes (§10.7).
- Query parameters (SPEC 10.11): dbzilla-core::params finds and substitutes placeholders in all six formats (colon, percent, question mark, dollar braces, dollar, double braces), skipping comments and, by default, quoted strings and dollar-quoted bodies. A Variables dialog (Apply, Cleanup, Cancel) asks for the values before a run when the feature is on; values are remembered for the session. Settings > Editor gained the enable switch, the format and the quoted-strings option. ParamFormat moved to core.
- Vim key binding: new dbzilla-vim crate (vim state machine, rope buffer with grouped undo, search, ex commands ported from the fed editor). Settings > Editor > Key binding (Default or Vim) turns it on for the SQL editor: Normal, Insert, Visual and command-line modes, block cursor, status line with mode and pending keys, yank goes to the system clipboard, :w saves the query. Only Ctrl+R is taken from the app shortcuts (redo). Edits made from outside vim (autocomplete, beautify) become one undoable step. Not verified visually yet.
- ER diagram (SPEC 11.3, read only): dbzilla-core::diagram builds tables and foreign key edges from the table structures, groups linked tables (shared colour, taken from the existing semantic colours so no new hue appears), sorts by name or column count, searches table and column names and lays the tables out in layers (referenced tables on the left, groups packed in rows, cycle safe). The `Conn::schema_structures` default method and the LoadDiagram command and Diagram event load every table of a schema in one request. New Diagram tab (Show Diagram in Open Anything): drag the canvas, drag a table, zoom with the buttons or Ctrl+scroll, Fit, Reset, Sort, Rearrange (reload and relayout), search with Enter to jump, double click opens the table, Workspace closes the tab. Not done yet: editing from the diagram, image export.
- ER diagram positions are persisted: dbzilla-store::diagrams keeps `diagrams.json` with the position of every table per server (driver, user, host, port, database), database and schema, so connections opened from the command line find them again. A new layout (first open, Rearrange, change of sort) and every table drag are saved; tables added since the last save keep their automatic position unless it lands on a saved table, then they move below. Rearrange forgets the saved positions.
- ER diagram inferred links: a column named id_X, X_id or xId (any case) with no foreign key gets a dashed grey line to the single primary key of the table X, Xs, Xes or Xies, when both columns have the same kind of type (integer or text). They never colour groups or move tables, and the "Inferred links (n)" checkbox in the toolbar hides them.
- Workspace toolbar: a button next to "New SQL editor" opens the ER diagram.
- ER diagram, linking columns: drag from the left or right edge of a column (a dot shows under the pointer) to a column of another table, or of the same one. A rubber band follows the pointer and the target row is highlighted. A dialog then asks what to make: a link only in the diagram (default, saved in diagrams.json next to the positions, drawn dashed in the secondary colour, deleted with a right click on the line) or a real foreign key with optional constraint name, On update and On delete, sent through the safe-mode gate like the other DDL. The last choice is remembered. Core: EdgeKind (Real, Inferred, Manual) replaces the inferred flag, `DocLink`, `Diagram::add_manual`; StructuralOp::AddForeignKey gained `current`, and SQLite now adds a foreign key by rebuilding the table (`sqlite_rewrite::add_table_constraint`), refused when other tables refer to it, and rolled back when existing rows break the key. The diagram reloads after the DDL.

- Release 0.4.0.
- Metrics board (SPEC 11.2): dbzilla-core::metrics holds the board model, `$name` variable substitution, refresh rules (1 s to 30 min, on event, manual), event wiring and the shaping of results for charts; dbzilla-store::metrics keeps the boards in `metrics.json`. New Metrics tab (toolbar bolt button, Show Metrics Board in Open Anything) with a pannable canvas of objects: data table, scoreboard, bar, line and pie charts, input field, dropdown (fixed or loaded from SQL) and button. Objects move and resize (unless locked), have a settings window (label, SQL, refresh rate, variable name and value, objects to refresh on an event), run their queries on the workspace session and refresh by themselves while the board is started. Boards can be created, renamed, duplicated, deleted, imported and exported as JSON. Not verified visually yet; Exporter, Importer and Connection objects are still missing.
- Notifications button in the toolbar uses a new alert icon (circle with an exclamation mark) instead of the bolt, which now belongs to the Metrics board.
- Process list (SPEC 11.4): dbzilla-core::processes builds the list and kill statements (PostgreSQL `pg_stat_activity` without background workers and the own session, `pg_cancel_backend`; MySQL and MariaDB `information_schema.processlist` without daemons, `KILL QUERY`), refuses ids that are not plain numbers, sorts (numbers by value, NULL last) and filters. The Process list sheet (toolbar console button, Process List in Open Anything) keeps its own connection, so it answers while the workspace is busy: refresh now or every 5 s, sortable columns, filter, multi-select with Mod and Shift, copy as text or CSV, Kill from the button or the context menu. A kill counts as a write for the safe mode: it asks for confirmation or the password like other changes. Other drivers get a message. Tested end to end on PostgreSQL 16 and MySQL 8.4 in Docker (a running sleep is listed, killed, and ends early).
- Backup and restore (SPEC 12.3): dbzilla-io::backup builds the `pg_dump`, `pg_restore`, `mysqldump` and `mysql` command lines (password only in `PGPASSWORD` or `MYSQL_PWD`, never in the arguments; PostgreSQL SSL mode in `PGSSLMODE`), finds the tools in a configured directory or the `PATH` with an install hint when missing, streams their output, supports cancel and removes the partial file of a failed or cancelled backup. Gzip is dropped for the PostgreSQL custom format; `pg_restore` refuses plain SQL files and points to the SQL dump import. SQLite is backed up as a `tar.bz2` holding the database and its `-wal`, `-shm` and `-journal` files, and restored beside the original as `name-restored.ext`; existing files are replaced only after an explicit checkbox. dbzilla-store::backup remembers options and tools directory per connection in `backup.json`. The Backup and restore sheet (toolbar folder button, Backup Database and Restore Database in Open Anything) has the Add option menu and a suggested file name; a restore goes through the safe mode. Tested with fake tools and SQLite round trips; not yet run against real pg_dump and mysqldump.
- User management (SPEC 11.5): dbzilla-core::users holds the user model (role attributes or global privileges, privileges per table or per database, MySQL per hour limits), the diff from the original to the edited user (`CREATE ROLE/USER`, `ALTER ROLE/USER`, `GRANT`, `REVOKE`, `DROP`; PostgreSQL revokes the known table privileges before `DROP ROLE`, which would fail otherwise), quoting of names and passwords, masking of passwords for display and history, and the parsing of `pg_roles`, `aclexplode` and `SHOW GRANTS`. The Users sheet (toolbar key button, User Management in Open Anything) keeps its own connection: user list with search, New user and Delete from the context menu, tabs General, Global privileges (with Check all, Uncheck all and a warning when everything is granted), Table or Database privileges (Available and Granted lists) and Resources for MySQL. The SQL preview is always visible, Apply goes through the safe mode and the statements are written to the history with the passwords masked. Statements checked against PostgreSQL 16 and MySQL 8.4 in Docker.
